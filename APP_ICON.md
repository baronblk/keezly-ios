# Keezly — App Icon

The icon, where it comes from, how it is installed, and exactly how far it has
been verified. The decision itself is **DEC-026**.

---

Three different questions, never merged into one answer (§167):

| Question | Status |
|---|---|

| **INTEGRATED** — the app target actually uses it | **DONE & VERIFIED** |

## What it is

`IconConcept.table` — four pieces round an engraved ring, on the board's own
maple. Three concepts were compared at every size an icon is really seen at;
the reasoning and what the other two failed at are in DEC-026.

No lettering. No SF Symbol. No stock shape. Every path is Keezly's own, drawn
from the same vocabulary as the board.

---

## The icon is code

`App/Keezly/Brand/AppIconArtwork.swift` draws it in SwiftUI. That file *is* the
editable source — there is no drawing-program original that can drift away from
the app.

| Script | What it does |
|---|---|
| `scripts/icon-install.sh` | Renders the three 1024 files and writes them into the asset catalogue |
| `scripts/icon-check.sh` | Re-renders and **fails** if the committed files no longer match the source |
| `scripts/icon-sheet.sh` | Writes every concept at every size, plus the tinted masks, for review |

---

## How it is wired

Checked rather than assumed:

| | Value |
|---|---|
| `ASSETCATALOG_COMPILER_APPICON_NAME` | `AppIcon` — set in `project.yml`, present in both the Debug and Release build configurations |
| Asset catalogue | `App/Keezly/Assets.xcassets/AppIcon.appiconset` with `AppIcon-1024.png`, `AppIcon-dark-1024.png`, `AppIcon-tinted-1024.png` |
| `Info.plist` | `CFBundleIconName = AppIcon`, with `CFBundleIcons` and `CFBundleIcons~ipad` generated by the asset compiler |
| Built app | Carries `AppIcon60x60@2x.png` and `AppIcon76x76@2x~ipad.png` |

`assetutil --info` on the **device** build's `Assets.car` reports four
renditions, which is what proves all three appearances ship:

```
('AppIcon', '(any)',                 758366 bytes, 1024)
('AppIcon', 'UIAppearanceDark',      716801 bytes, 1024)
('AppIcon', 'ISAppearanceTintable',   18563 bytes, 1024)
```

The tinted one is small because it is a greyscale mask, which is what iOS
expects to tint for itself.

### A note on what a generic icon beside Keezly means

The iPad home screen also shows a plain grid icon next to Keezly. That is
`KeezlyUITests-Runner`, the XCUITest runner, which has no icon and is not
supposed to have one. It is installed by any UI test run and is not part of
the app.

If a device shows Keezly itself with a generic icon, the cause is an install
that predates the icon. A clean reinstall fixes it; iOS caches home-screen
artwork per installed bundle.

## Quality

Held to by `AppIconTests`, which fails:

- a concept that flattens towards one colour at **29 points**,
- a concept that loses its shape as a **tinted mask**,
- a set of concepts that turn out to be one picture three ways.

Rendered and checked at **1024, 180, 120, 60, 40 and 29**. The 1024 master is
opaque, as the App Store requires — no alpha, no transparency, no rounded
corners of its own.

---

## What would make it DEVICE VERIFIED

Looking at the home screen of the physical iPad and the physical iPhone after a
clean install, and confirming the icon and its dark variant. Everything needed
for that is installed on the iPad already.
